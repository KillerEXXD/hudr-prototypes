ClubrGO — Slow-Reveal Onboarding

The app grows as the user does. A brand-new player isn't dropped onto four empty tabs — the navigation and surfaces unlock one meaningful step at a time: join a club, then host or play, then a live game. Profile lives on the top-right avatar, so there's no "Me" tab to reveal at all.

Nothing dead-ends · the nav never looks broken · an account that empties returns to the welcome.

Fresh — no club Pending — request sent Member — joined a club Host — created a club Playing — in a game Settled — finished one
1.

Why slow reveal

A poker side-games app is only useful once you're in a club. Showing Clubs, Games and Me to someone with zero clubs is four dead tabs and a confusing first run. So we reveal the app in step with the user's real footprint.

The problem

🧱 Four empty tabs on day one

A new sign-up saw Discover · Clubs · Games · Me immediately — but with no club, Games is empty, Clubs is empty, and "Me" duplicates the avatar. Joining one club then revealed Clubs and Games together, even before there was a game to play.

😵 Empty Games / Clubs🔁 Me duplicates the avatar⏩ Too much, too soon
The fix

🌱 Grow the app with the user

No nav until you're in a club. Joining reveals just Discover + Clubs. Games appears only when you're actually in a game. Me is never a tab — it's the avatar, top-right, from minute one.

One step at a timeNever a dead tabProfile = avatar

5.

Pending — you don't leave the welcome

When you request a club, you stay on the same hub. A "Waiting on [club]" banner pins to the top; everything else (more clubs to join, invite code, how-it-works) stays right where it was — so you can keep exploring while the host reviews. Still no bottom nav — you're not in yet.

🙋

Request a club

Tap "Request" on a club, or paste an invite code.

⏳

Banner pins on top

"Waiting on 🃏 Aces High — the host will admit you." The hub stays below it.

✅

Admitted → Member

The banner clears, nav reveals Discover + Clubs.

Tapping "Clubs to join → See all" opens the full list, which also has a "Create a club" button; Back returns you here — no nav commitment yet.

6.

Member vs Host — the branch

Joining a club and creating a club are two doors out of the welcome. Both unlock a two-tab nav, but they land on different homes.

Joined a club · Member

🧭 Discover + Clubs

Discover leads with the open games in your clubs and more clubs to join; the how-it-works education shrinks to one small "New here?" disclosure. Clubs shows your club + suggested clubs to join at the bottom.

Games-led DiscoverClubs = mine + suggestedNo Games tab yet
Created a club · Host

🏠 Home + Clubs

Home is a host's first-run 3-step checklist (create a game → invite players → share the link) + your club's games + a short "how hosting works" note. The how-club-works card & invite-code panel are gone — you already know.

First-run checklistHost-framed educationno how-club-works / invite

How hosting works (the reworded education): create or join a club first → the host creates a game and shares the game link with members (or members find it on the Club details page) → then each game type plays out as usual.

7.

Now playing — the Games tab arrives

Until you're actually in a game, you find games inside a club (Discover's "open now" list, or the club's Games tab). The moment a host approves you into a game, two things appear:

🎮

The Games tab unlocks

Now you have somewhere to track every game you're in — so the tab finally earns its place.

⚡

"Your game is on → Open"

A live card pins to the top of Discover, one tap back into the action.

A pending game request does not count — only an approved, live entry reveals the tab, so it never appears prematurely.

8.

Empty reset — back to welcome

The reveal is monotonic with one deliberate exception: if a user ends up with zero clubs of any kind and no games (e.g. they leave their only club), the app returns them to the cold-start welcome with the nav hidden — instead of a hollow Discover. A partial shrink (still in some club) keeps the nav. Gated on loaded data, so it never flickers while things load.

9.

The rules that hold it together

📈

Footprint-driven

Stage = what you've actually done (member? host? in a game? finished one?). One pure resolver, easy to test.

🔒

Monotonic reveal

A tab, once shown, stays — the nav never visibly regresses on a partial change. Only a fully empty account resets.

2️⃣

Two-tab minimum

A lone Home tab hides the whole bar, so a fresh user simply has no nav — never one orphan tab.

🏷️

Role-labelled first tab

Players see Discover; hosts see Home. Same slot, different home.

🙂

Me = avatar, always

Profile, settings & logout sit on the top-right avatar from minute one. No "Me" tab to gate.

🚫

Nothing dead-ends

Every empty state offers a next step — join a club, create one, find a game.
